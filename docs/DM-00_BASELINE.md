# DM-00 — 1차 개발의 로컬 검증 기준선

작성일: 2026-09-25 / 갱신일: 2026-09-26

범위 변경: 최초에는 로컬 코드·자동 테스트만 진행했습니다. 이후 사용자가 현재 연결 DB의 **새 테스트 계정·그림·드래곤 생성과 해당 데이터 정리**를 승인했습니다. 기존 플레이어 데이터·운영 설정·스키마 변경, 유료 AI 호출, 배포는 이번 범위에 포함하지 않습니다. 실제 쓰기는 인증 수단 부재로 아직 수행하지 않았습니다.

## 이번 구현

- CMS 등록 요청을 테이블별 스키마로 분기해 `useCms.ts`의 삽입 타입 오류를 수정했습니다. DB의 필수값 검사와 RLS는 그대로 유지합니다.
- 라우터 오류 화면에 라이브러리의 `ErrorComponentProps`를 적용하고 `unknown` 오류를 안전하게 처리합니다.
- 깨끗한 설치에서 확인한 이미지 서버 함수의 `.validator` 호환성 오류를 `.inputValidator`로 수정했습니다.
- `package-lock.json`을 현재 `package.json`과 동기화했습니다. 실행 중인 미리보기의 `node_modules`는 변경하지 않았습니다.
- `npm run typecheck`, `npm run check`, `npm run check:environment`를 추가했습니다.
- GitHub Actions의 설치를 Node 24.14.1 + `npm ci`로 통일하고 잠금 파일 캐시 키를 수정했습니다. 타입 검사·테스트·빌드는 린트 작업과 독립적으로 실행하여 기존 린트 오류에 가려지지 않게 했습니다. 린트 검사는 제거하거나 완화하지 않았습니다.
- 기존 CI의 HTML 보고서 문자열이 YAML 블록 밖으로 벗어나 파싱에 실패하던 들여쓰기도 수정했습니다.
- CMS 테이블 9종의 요청 전달·DB 오류 보존 10개와 환경·잠금 파일 점검 6개 테스트를 추가했습니다.
- 전체 소스 포맷을 ESLint 자동 수정으로 정리하고, Supabase/결제 이벤트의 `any`를 실제 스키마 타입으로 교체했습니다. 타입을 맞추기 위해 린트 규칙을 끄지 않았습니다.
- 전투 타이머의 최신 상태 참조, 콜백 의존성, `const` 선언을 정리했습니다. UI의 스타일 상수·컨텍스트와 라우터 오류 화면을 별도 파일로 분리해 Fast Refresh 경고를 해결했습니다.
- `.gitattributes`에 소스 파일 LF 정책을 추가해 Windows/Linux 줄바꿈 차이로 포맷 오류가 재발하지 않도록 했습니다. 변경 파일 상당수는 포맷 변경입니다.
- `check:database`(읽기 전용)와 `test:storage`(명시적 대상 확인 후 테스트 쓰기·정리)를 추가하고 실행 안전장치 5개를 테스트했습니다. 운영 설정을 변경하는 기존 `test:ownership`은 실행하지 않았습니다.
- 후속 401 진단: 스키마 루트 거절을 전체 연결 실패로 간주한 문제를 수정했습니다. Auth 설정·DB 0행 조회를 분리하고, 실제 키 거절/권한 오류/비정상 응답/네트워크 실패를 놓치지 않는 회귀 테스트 7개를 추가했습니다. 응답 본문·키·사용자 데이터는 출력하지 않습니다.

## 재현 절차

검증 환경: Windows, Node 24.14.1, npm 11.11.0. 기준 잠금 파일은 `package-lock.json`입니다. 기존 `bun.lock`과 Bun 기반 DB 통합 테스트 스크립트는 보존하지만 이번 npm/CI 기준선에는 사용하지 않습니다.

```sh
npm ci
npm run check:environment
npm run check
npm run dev
```

- `npm ci`는 기존 `node_modules`를 교체합니다. 개발 서버를 종료한 뒤 실행하거나 별도 체크아웃에서 검증합니다.
- `check`는 타입 검사 → 단위 테스트 → 빌드이며, `lint:ci`는 별도 검사입니다. `npm run ci`는 둘 모두를 요구합니다. 현재 전체 린트가 오류·경고 0으로 통과합니다.
- `check:environment`는 변수의 존재 여부와 최상위 의존성 선언 일치만 확인합니다. 값·키를 출력하지 않고, 네트워크 요청이나 DB 쓰기를 하지 않습니다. 전체 의존성 해석은 `npm ci`로 검증합니다.
- `.dev.vars`는 별도 Worker 설정으로만 표시합니다. 파일의 존재를 Vite 개발 서버나 배포 환경의 실제 변수 주입으로 간주하지 않습니다.
- 개발/운영 모드 파일의 존재 검사는 `npm run check:environment -- development` / `production`으로 구분할 수 있습니다. `production`도 로컬 파일 검사이지 배포 서버 조회가 아닙니다.

최초 린트는 오류 24,549 / 경고 12였습니다(포맷 24,531, `no-explicit-any` 11, `prefer-const` 7). 후속 작업에서 전체 소스 포맷과 타입·Hook·Fast Refresh 문제를 정리했습니다. 수치는 현재 작업 디렉터리의 의존성으로 측정했습니다. 별도 새 설치의 50개 테스트·빌드는 앞선 잠금 파일 검증 결과이며, 현재 62개 결과와 구분합니다. 설치 로그에는 `whatwg-encoding` 사용 중단 경고가 있었으며, 취약점 검사는 이번 설치에서 실행하지 않았습니다.

빌드는 통과했지만 500kB 초과 클라이언트 청크, 의존성의 미사용 import 및 `use client` 처리, Nitro의 Wrangler `main` 재정의 경고가 남았습니다. 현재 미리보기 의존성에서는 `.inputValidator` 사용 중단 경고도 발생하지만, 기준 잠금 파일의 이전 API와 호환되도록 유지했습니다. 빌드 성공은 실행 성능이나 실제 배포 성공의 증거가 아니며, 별도 성능·배포 검증 대상으로 유지합니다.

## AI 설정 확인

OpenAI Docs를 통해 현재 기본 모델 `gpt-image-2.5-sunburst`가 이미지 편집을 지원하는 모델임을 확인했습니다. 모델 이름은 변경하지 않았습니다. 이는 이 프로젝트 계정의 접근 권한이나 호출 성공을 뜻하지 않습니다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)

로컬 검사에서 `OPENAI_API_KEY`는 없었습니다. API 키 값은 기록하지 않았고 모델 목록 조회나 유료 이미지 생성은 하지 않았습니다. AI가 없어도 원본 이미지로 진행하는 기존 경로는 유지합니다.
