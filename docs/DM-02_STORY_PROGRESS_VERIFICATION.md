## 적용 결과

- 적용 전 `public.dragon_story_progress`는 없었고 `owned_dragons`, `set_updated_at()` 및 DM-01 마이그레이션 이력을 확인했습니다.
- [`20260927130000_dm02_dragon_story_progress.sql`](../supabase/migrations/20260927130000_dm02_dragon_story_progress.sql)의 테이블·인덱스·정책·권한·트리거를 트랜잭션으로 적용하고 `supabase_migrations.schema_migrations`에 버전을 기록했습니다.
- 적용 후 테이블 존재, RLS 활성화, 소유자 정책 4개, 사용자 정의 갱신 트리거 1개, 해당 이력 1건을 읽기 전용 조회로 확인했습니다.
- 기존 `story_saves`와 드래곤·계정·그림·초안 데이터는 삭제하거나 초기화하지 않았습니다.

## 브라우저·DB 검증

재사용 중인 테스트 계정의 `DM01D 테스트 드래곤`으로 로컬 앱(`localhost:8080`)에서 확인했습니다.

| 흐름                      | 결과                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| 첫 만남 한 장면 진행      | `my_dragon` / `meeting` / `v1`이 클라우드에 저장됨                 |
| 첫 만남 새로고침·이어하기 | 같은 `meeting` 장면과 선택지가 복원됨                              |
| 성장 한 장면 진행         | 같은 드래곤의 `dragon_growth` / `Node_3` / `v1`이 별도 행에 저장됨 |
| 성장 새로고침·이어하기    | `Node_3` 훈련 장면이 복원됨                                        |
| 성장 후 첫 만남 재진입    | 성장 저장에 덮이지 않고 `meeting` 장면이 다시 복원됨               |

성장 게시 장면 진입 과정에서 테스트 계정에 해당 장면의 기존 보상(400G·능력 포인트 +1)이 지급됐습니다. 이 테스트 계정·드래곤·진행·보상은 사용자의 재사용 요청에 따라 유지합니다.

## 아직 검증하지 않은 범위

- 같은 챕터에서 두 드래곤의 진행 분리 및 타 계정 RLS 차단의 별도 실측
- `v1` 이후 이야기 버전 전환·이전 데이터 처리
- 물리적으로 다른 기기와 배포 서비스에서의 복원
- 첫 만남 → 1권 각색 → 성장의 연속 완주, 최종 성장 반영과 완료 보상 중복 방지

현재 한 칸에 남은 `story_saves`만 새 테이블로 옮길 수 있습니다. 과거에 덮여 사라진 장면은 복구할 수 없습니다. 위 미검증 항목이 남아 있으므로 DM-02 전체 완료로 표시하지 않습니다.
