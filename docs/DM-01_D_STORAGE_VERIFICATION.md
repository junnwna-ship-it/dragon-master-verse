## 코드 수정

초안을 폐기한 후 새 초안을 만들 때 이전 초안의 클라우드 revision이 ref에 남아 새 draft ID의 저장과 충돌할 수 있었습니다. [`useDragonDraft.ts`](../src/hooks/useDragonDraft.ts)에서 폐기·로컬 삭제가 끝난 뒤 revision을 0으로 초기화했습니다. 실제 API 검증 스크립트는 재로그인, private 파일 복원, 소유자 격리, 생성 멱등성을 재실행할 수 있게 남겼습니다.

2026-09-27 후속 점검에서 로그아웃 상태의 랜딩 ‘기존 계정으로 입장’이 `/app`으로 이동했다가 다시 랜딩으로 돌아오는 경로를 수정했습니다. 별도 `localhost` 브라우저 저장 영역에서 이 버튼을 누르면 로그인 창이 열리는 것을 실제 UI로 확인했습니다. 이미 로그인된 계정의 초안에는 쓰기 작업을 하지 않았습니다. 두 기기의 클라우드 revision이 충돌할 때는 로컬 초안 삭제를 차단하고 ‘초안 충돌 다시 확인’으로 표시하도록 보완했습니다. 타입 검사, 린트, 기존 자동 테스트 136개 및 프로덕션 빌드가 통과했습니다. 이 점검은 실제 계정 로그인·파일 업로드·동시 편집 복구를 증명하지 않습니다.

## 남은 완료 조건

2026-09-27 실제 제작 UI에서도 일회용 계정 `dm01d-ui-bd600f97@artiati.local`로 로그인하고, 저장소의 예시 그림을 업로드했습니다. 오른쪽 회전·왼쪽 10% 자르기 후 원본/편집본 선택, 이름·속성·첫 만남·성장 목표 입력, 클라우드 저장, 다른 브라우저 주소에서 초안·그림 복원, 드래곤 등록 및 로비 카드 표시까지 확인했습니다. 이 계정과 테스트 드래곤은 실기기 검증을 위해 **아직 보존 중**이며 영구 삭제 전 사용자 확인이 필요합니다. 그림은 실제 사용자 그림이나 휴대전화 카메라 사진이 아닙니다.

다른 브라우저 주소에서 초안을 다시 저장할 때 Storage가 `The resource already exists`를 반환하는 오류가 발견되었습니다. `dragonCloudStorage.ts`는 이제 기존 파일을 비공개 다운로드해 크기와 SHA-256 해시가 원본과 모두 일치할 때만 중복 업로드를 허용합니다. 수정 후 같은 단계 이동에서 클라우드 동기화를 확인했습니다. 등록 직후 첫 만남 화면에는 `This chapter has no published scenes yet.`가 표시됐습니다. 이후 DM-02 로컬 코드에서 개인 챕터의 게시 장면이 없는 경우에만 대체 장면을 제공했습니다. 테스트 계정의 브라우저에서 새 첫 만남 장면, 선택지 전환 및 새로고침 뒤 같은 장면으로 이어하기를 확인했습니다. 성장 챕터는 게시된 DB 장면이 우선 표시되는 것을 확인하고 첫 장면만 열었습니다. 해당 테스트 계정의 이야기 진행도 재사용을 위해 유지합니다.

- 플레이어 제작 화면의 업로드·자르기·선택·저장·등록: 예시 그림으로 확인 완료. 실제 손그림은 미검증.
- 두 브라우저 주소(`localhost:8080`, `127.0.0.1:8081`)에 로그인된 위 일회용 계정에서 같은 초안을 편집해 `DRAFT_CONFLICT`를 실제 재현했습니다. 오래된 기기 버전의 편집·삭제가 차단되고 이름·그림 비교가 나타났습니다. 클라우드 버전을 선택하면 기기 초안이 IndexedDB `conflicts`에 보관됐고, 보관 사본을 다시 선택하면 현재 클라우드 버전도 별도로 보관된 뒤 사본이 클라우드에 저장됐습니다. 반대 브라우저 재진입에서 복구된 내용을 확인했고, 사본 2개가 페이지 재진입 후에도 보였습니다. 이 검증은 실제 휴대전화 등 **물리적으로 다른 기기 검증은 아닙니다.**
- 완료된 드래곤 초안이 오래된 브라우저에 남은 경우 `INVALID_ASSET`로 재업로드를 시도하는 문제를 발견했습니다. 완료 상태를 먼저 조회해 같은 드래곤 UUID로 다시 불러오도록 수정했고, 실제 시험 계정 UI에서 확인했습니다. 클라우드에 이미 저장됐던 초안이 아예 없는 경우에도 자동 재업로드를 멈추고 기기 사본을 보존합니다.
- 완료된 로컬 초안과 다른 기기의 새 활성 초안이 동시에 있을 때는 완료본을 먼저 기기 보관함에 보존한 뒤 새 초안으로 전환합니다. 이 분기와 실제 그림이 포함된 충돌 사본의 화면 복원은 자동 검사만 통과했거나 아직 실브라우저 검증 전입니다.
- 점검 중 `127.0.0.1:8080`이 테스트 계정이 아닌 다른 로그인 계정임을 확인하기 전에 시험 이름을 입력해, 그 계정에 `DM01D 충돌 검증 · 기기`라는 활성 초안 1개(`36e7086a-399d-45b4-b02b-1dbf106badf2`, 원본 그림 없음)가 생성됐습니다. **사용자 요청에 따라 이 초안과 계정, DM-01-D 테스트 계정·드래곤·초안을 모두 삭제하지 않고 유지합니다.** 향후 해당 초안을 다룰 때는 계정 소유자와 범위를 먼저 다시 확인합니다.
- 실제 휴대전화 카메라 촬영, EXIF 방향과 용량별 업로드 확인.
- 물리적으로 다른 기기에서 로그인해 앨범·초안을 다시 여는 과정 확인.
- AI 정돈 요청 중단 후 재개와 사용량/비용 제어는 별도 검증. 이번에는 유료 AI를 호출하지 않았습니다.
- Supabase 생성 타입 갱신과 배포된 버전 확인.

새 인증 클라이언트는 저장소가 없는 세션을 모사합니다. 이것으로 물리적 다른 기기·실제 게임 UI 검증을 완료한 것으로 표시하지 않습니다.
