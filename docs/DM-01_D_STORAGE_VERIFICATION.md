## 이번에 확인한 흐름

연결 대상은 Lovable Dragon Masters의 `mcwafbwjpkjtvqfenqys` DB입니다. 관리자 화면에서 일회용 이메일·암호 계정 2개를 만들고, 공개 Supabase 키를 사용하는 별도 인증 클라이언트로 실제 API를 호출했습니다. 두 계정은 테스트 접두사 `dm01d-`를 사용했습니다. 실제 사용자 계정과 그림은 사용하지 않았습니다.

재실행 도구는 [`verify-dm01-cloud.mjs`](../scripts/verify-dm01-cloud.mjs)입니다. `DM01_OWNER_EMAIL`, `DM01_OWNER_PASSWORD`, `DM01_OTHER_EMAIL`, `DM01_OTHER_PASSWORD`를 프로세스 환경 변수로 공급하고 `node scripts/verify-dm01-cloud.mjs --write --project=mcwafbwjpkjtvqfenqys`로 실행합니다. `dm01d-owner-` / `dm01d-other-` 접두사의 별도 시험 계정만 받습니다. 실행은 시험 데이터를 생성하므로, 출력된 draft/dragon ID와 경로를 기준으로 Storage 파일을 먼저 삭제한 후 해당 시험 행·계정만 정리해야 합니다. 암호는 Git·출력·문서에 기록하지 않습니다.

## 코드 수정

초안을 폐기한 후 새 초안을 만들 때 이전 초안의 클라우드 revision이 ref에 남아 새 draft ID의 저장과 충돌할 수 있었습니다. [`useDragonDraft.ts`](../src/hooks/useDragonDraft.ts)에서 폐기·로컬 삭제가 끝난 뒤 revision을 0으로 초기화했습니다. 실제 API 검증 스크립트는 재로그인, private 파일 복원, 소유자 격리, 생성 멱등성을 재실행할 수 있게 남겼습니다.

2026-09-27 후속 점검에서 로그아웃 상태의 랜딩 ‘기존 계정으로 입장’이 `/app`으로 이동했다가 다시 랜딩으로 돌아오는 경로를 수정했습니다. 별도 `localhost` 브라우저 저장 영역에서 이 버튼을 누르면 로그인 창이 열리는 것을 실제 UI로 확인했습니다. 이미 로그인된 계정의 초안에는 쓰기 작업을 하지 않았습니다. 두 기기의 클라우드 revision이 충돌할 때는 로컬 초안 삭제를 차단하고 ‘초안 충돌 다시 확인’으로 표시하도록 보완했습니다. 타입 검사, 린트, 기존 자동 테스트 136개 및 프로덕션 빌드가 통과했습니다. 이 점검은 실제 계정 로그인·파일 업로드·동시 편집 복구를 증명하지 않습니다.

## 남은 완료 조건

2026-09-27 실제 제작 UI에서도 일회용 계정 `dm01d-ui-bd600f97@artiati.local`로 로그인하고, 저장소의 예시 그림을 업로드했습니다. 오른쪽 회전·왼쪽 10% 자르기 후 원본/편집본 선택, 이름·속성·첫 만남·성장 목표 입력, 클라우드 저장, 다른 브라우저 주소에서 초안·그림 복원, 드래곤 등록 및 로비 카드 표시까지 확인했습니다. 이 계정과 테스트 드래곤은 실기기 검증을 위해 **아직 보존 중**이며 영구 삭제 전 사용자 확인이 필요합니다. 그림은 실제 사용자 그림이나 휴대전화 카메라 사진이 아닙니다.

다른 브라우저 주소에서 초안을 다시 저장할 때 Storage가 `The resource already exists`를 반환하는 오류가 발견되었습니다. `dragonCloudStorage.ts`는 이제 기존 파일을 비공개 다운로드해 크기와 SHA-256 해시가 원본과 모두 일치할 때만 중복 업로드를 허용합니다. 수정 후 같은 단계 이동에서 클라우드 동기화를 확인했습니다. 등록 직후 첫 만남 화면에는 `This chapter has no published scenes yet.`가 표시되어, 스토리 콘텐츠 연결은 별도 후속 과제입니다.

- 플레이어 제작 화면의 업로드·자르기·선택·저장·등록: 예시 그림으로 확인 완료. 실제 손그림은 미검증.
- 브라우저 두 개에서 같은 초안을 편집했을 때 충돌 안내와 **양쪽 초안을 보존하는 복구 흐름** 확인. 현재는 충돌 감지와 로컬 삭제 차단만 구현되어 있으며 어느 쪽을 선택할지 결정·복구하는 화면은 남아 있습니다.
- 실제 휴대전화 카메라 촬영, EXIF 방향과 용량별 업로드 확인.
- 물리적으로 다른 기기에서 로그인해 앨범·초안을 다시 여는 과정 확인.
- AI 정돈 요청 중단 후 재개와 사용량/비용 제어는 별도 검증. 이번에는 유료 AI를 호출하지 않았습니다.
- Supabase 생성 타입 갱신과 배포된 버전 확인.

새 인증 클라이언트는 저장소가 없는 세션을 모사합니다. 이것으로 물리적 다른 기기·실제 게임 UI 검증을 완료한 것으로 표시하지 않습니다.
