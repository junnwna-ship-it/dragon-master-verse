# 나만의 드래곤 경험 — 개선 분석과 실행 로드맵

작성일: 2026-09-25

분석 기준: `e891cc0` (모바일·PC 반응형 UX/UI 개선)

문서 상태: 실행 계획 수립. 아래 신규 작업은 구현 완료가 아니라 예정 사항입니다.

## 1. 제품의 중심

> 내가 그린 드래곤이 내가 지은 이름으로 반응하고, 함께한 모험을 기억한다.

이 게임의 중심은 드래곤 수집이나 랭크 경쟁이 아니라 **플레이어가 직접 만든 드래곤과 이야기를 함께 만드는 경험**입니다. 덱·훈련·전투·상점은 이를 보조합니다.

- 플레이어가 주인공이며, 원작 인물은 동료·멘토·임무 제공자의 역할을 맡습니다.
- 원작 각색 모험과 사용자 창작 모험은 구분해서 표시합니다. 게임 고유 규칙을 원작 설정으로 소개하지 않습니다.
- AI는 사용자의 그림과 이야기를 보조합니다. 사용자가 결과를 확인하고 선택하며 원본을 잃지 않아야 합니다.
- 그림 실력, 이미지 생성 비용, AI 정돈 여부가 드래곤의 전투력을 결정하지 않습니다.
- 성장 후에도 처음 그린 드래곤의 특징이 유지되어야 합니다.

## 3. 확정 작업 순서와 진행 관리

이 문서를 작업 순서와 상태의 기준으로 사용합니다. README에는 요약과 링크만 유지합니다. 각 단계의 완료 기준을 충족한 뒤 다음 단계로 이동하고, 미완료 항목은 완료로 표시하지 않습니다.

| 순서 | 작업 ID | 우선순위 | 산출물 | 선행 작업 | 현재 상태 |
| --- | --- | --- | --- | --- | --- |
| 0 | DM-00 | P0 | 실행 환경·배포·저장 기준선 확인 | 없음 | 예정 |
| 1 | DM-01 | P0 | 드래곤 정체성·그림 원본·제작 초안 보관 | DM-00 | 예정 |
| 2 | DM-02 | P0 | 내 드래곤과 이야기 연결, 첫 성장까지의 최소 모험 | DM-01 | 예정 |

### DM-00. 실행 환경과 저장 기준선 확인

- [ ] 현재 빌드·테스트 결과를 다시 기록하고 기존 TypeScript 오류 2개(`useCms.ts`, `router.tsx`)를 정리합니다.
- [ ] README에 기록된 의존성 잠금 파일 불일치를 확인하고 재현 가능한 설치 절차를 마련합니다.
- [ ] 대상 서비스에 개인 드래곤 생성·스토리 마이그레이션이 적용되었는지 확인합니다. 적용이 필요한 경우 대상 환경과 범위를 확인한 후 진행합니다.
- [ ] AI 서버 설정과 실제 사용 가능한 모델을 확인합니다. 문서나 기본 설정만으로 호출 성공을 가정하지 않습니다.
- [ ] 시험용 계정·그림·허용된 AI 호출 범위를 정하고, 운영 데이터와 구분합니다.
- [ ] 사용자 소유 드래곤과 공유 카탈로그를 구분하고 서버 접근 제어를 확인합니다.

완료 기준: 설치·테스트·빌드 절차가 재현되고, 업로드 → 생성 → 재접속 조회의 저장 기준선과 배포 상태가 기록되어 있습니다. 유료 호출이나 운영 반영이 승인되지 않았다면 해당 항목은 미검증으로 남깁니다.

### DM-01. 드래곤 정체성과 그림을 보존

- [ ] 영구 드래곤 ID를 기준으로 그림·이야기·성장 기록을 연결합니다. 표시 순서에 따라 바뀌는 숫자 ID에 영구 기록을 의존하지 않습니다.
- [ ] 이름·원소·성격·성장 목표·보존할 외형 특징을 독립된 데이터로 관리합니다. 소개문은 이 데이터에서 생성합니다.
- [ ] 원본, AI 정돈본, 현재 선택본, 성장 이미지를 별도 자산과 버전으로 저장합니다.
- [ ] 촬영 이미지의 자르기·회전·방향 보정을 제공합니다.
- [ ] 원본과 AI 결과를 나란히 비교하고 사용자가 선택하게 합니다. AI 실패 시 원본으로 진행할 수 있게 합니다.
- [ ] 이름·설정·업로드 상태를 초안으로 보관하고 화면 재진입 시 복구합니다.
- [ ] AI 처리의 요청 상태·실패·재시도·중복 요청 방지를 관리합니다.

완료 기준: AI 재생성과 페이지 새로고침 뒤에도 원본과 초안을 잃지 않고, 선택한 이미지가 해당 드래곤에 정확히 연결됩니다. 생성 실패와 재시도 시 중복 드래곤이나 잘못 연결된 이미지가 생기지 않습니다.

후속 확장: 정돈 강도(선 정리 / 색칠 보완 / 게임 일러스트), 뿔·날개·문양 보존 옵션, 부분 수정. 이 확장은 원본 보관과 기본 생성 흐름이 안정된 뒤 진행합니다.

### DM-02. 내 드래곤과 이야기를 하나로 연결

- [ ] 기존 챕터와 창작 스토리가 공통된 플레이어·동행 드래곤 정보를 받도록 연결합니다.
- [ ] 진행 저장을 사용자·드래곤·스토리·스토리 버전으로 구분합니다. 기존 저장 데이터의 이전 정책을 포함합니다.
- [ ] 이름뿐 아니라 원소·성격·능력·이전 선택을 장면 조건에 사용할 수 있게 합니다.
- [ ] 원작 드래곤 이름만 바꿔 남는 외모·능력의 모순을 점검하고 역할·능력에 맞는 문장으로 수정합니다.
- [ ] 배경과 내 드래곤 이미지를 분리 배치하여 장면마다 외형이 달라지는 문제를 줄입니다.
- [ ] 첫 만남 → 작은 어려움 → 선택 → 첫 성장으로 끝나는 짧은 모험을 완성합니다.
- [ ] 이름에 반응하거나 고개를 기울이는 작은 첫 만남 연출을 넣습니다.
- [ ] 보상과 성장 사건의 중복 적용을 방지합니다.

완료 기준: 서로 다른 두 드래곤으로 같은 이야기를 플레이해도 진행과 기억이 섞이지 않습니다. 모바일에서 시작하고 PC에서 이어갈 수 있으며, 첫 성장 결과가 다시 로그인해도 유지됩니다.

1차 출시 범위: DM-00~02. 장편 자동 생성이나 랭크 경쟁보다 이 짧은 경험을 먼저 완성합니다.

### DM-03. 질문형 이야기 제작과 장면 편집

- [ ] 시작 질문 네 가지를 제공합니다: 모험 장소 / 도와줄 상대 / 어려움 / 배울 것.
- [ ] 템플릿으로 3~5개 장면 초안을 만들고, 선택적 AI 초안 기능은 사용자가 확인한 뒤 확정하게 합니다.
- [ ] 장면 카드에서 배경·등장인물·드래곤 표정·대사·선택지·다음 장면을 편집합니다.
- [ ] 이미지 URL 직접 입력 외에 업로드와 기존 자산 선택을 지원합니다.
- [ ] 기존 텍스트 편집기는 고급 모드로 유지하고, 형식 변환 시 내용 손실을 검사합니다.
- [ ] 끊어진 선택지, 존재하지 않는 장면, 도달할 수 없는 엔딩을 저장·공개 전에 안내합니다.
- [ ] 초안 자동 저장과 버전 복원, 편집 중 미리보기를 제공합니다.
- [ ] 공개는 기본 비공개에서 시작하고 공개 전 확인·신고·숨김 흐름을 마련합니다.
- [ ] 원작 각색·사용자 창작·템플릿의 표기를 구분하고 오해를 부르는 ‘공식’ 표기를 정리합니다.

완료 기준: 장면 문법이나 Node ID를 몰라도 처음부터 끝까지 플레이할 수 있는 이야기를 만들 수 있습니다. 공개 전 미리보기와 연결 검증이 가능하고, 기존 이야기는 계속 열립니다.

### DM-04. 기억·관계·성장 앨범

- [ ] 능력 성장, 관계 성장, 서사 성장을 구분합니다.
- [ ] 중요한 선택을 구조화된 기억 사건으로 저장합니다. 자유로운 AI 요약만으로 사실을 결정하지 않습니다.
- [ ] 이후 장면이 저장된 기억을 참조해 반응하게 합니다.
- [ ] 첫 비행·첫 구조·새 능력 습득을 성장 조건과 연결합니다.
- [ ] 외형 변화 전후를 비교하고 사용자가 적용 여부와 현재 모습을 선택하게 합니다.
- [ ] 원본 그림·첫 만남·중요 선택·성장 모습을 시간순 모험 앨범으로 보여줍니다.
- [ ] 실패도 연습과 재도전의 기록으로 남기며, 돌봄을 놓쳤다고 관계를 과도하게 벌주지 않습니다.

완료 기준: 이전 선택이 다음 장면의 반응에 실제 영향을 줍니다. 성장 후에도 원본 특징을 유지하고 이전 모습으로 돌아갈 수 있으며, 기록이 다른 드래곤과 섞이지 않습니다.

### DM-05. 덱·능력·밸런스

- [ ] 이름으로 판정하는 패시브를 능력 ID와 설정 데이터로 분리합니다. 이름 변경으로 능력을 얻거나 잃지 않게 합니다.
- [ ] 사용자 드래곤도 기본 기술·고유 기술·성장으로 배우는 기술을 갖게 합니다.
- [ ] 표시 속성과 실제 전투 속성을 일치시킵니다. 현재 빛→금속, 그림자→대지 매핑의 유지 여부를 구현 전에 결정하고 데이터 이전 영향을 기록합니다.
- [ ] MP 총량 투자 효과, 기술 비용, 공격·방어·체력의 효용을 테스트합니다.
- [ ] 그림 품질·AI 정돈 여부와 무관한 동일 능력치 예산을 마련하고 서버에서 검증합니다.
- [ ] 이야기 덱과 자유 대결 덱을 구분하고, 초반 동료 대여를 지원합니다.
- [ ] 역할·상성·교체 이유와 추천 덱을 이해하기 쉬운 말로 안내합니다.
- [ ] 현재 대결을 연습 상대 방식으로 명확히 표시합니다. 실시간 경쟁으로 소개하지 않습니다.

완료 기준: 임의로 이름을 지은 드래곤도 역할과 고유 능력을 사용합니다. 이름 변경·덱 교체·속성 판정이 회귀 테스트를 통과하고, 서버가 허용 범위를 벗어난 능력치와 보상을 받아들이지 않습니다.

### DM-06. 이펙트·음향·성능

## 4. 권장 게임 구성

### 그림과 장면

원본 그림 → 정돈 후보 → 선택된 캐릭터 → 장면별 배치 → 승인된 성장 모습으로 이어갑니다. 배경과 캐릭터를 분리하고 동일한 특징 정보를 재사용합니다. 얼굴·손·책상 등이 포함된 촬영은 자르기 안내로 줄이고, 공개 전 결과를 확인하게 합니다.

### 기억이 이어지는 이야기 예시

겁이 많은 루미가 다리를 건너지 못하는 장면에서 기다려주면 신뢰 사건을, 함께 연습하면 용기 사건을 기록합니다. 다음 이야기에서 해당 사건이 있을 때만 ‘지난번에도 함께 기다려줬잖아’ 같은 반응을 사용합니다. 모든 선택을 단순 정답/오답으로 처리하지 않습니다.

### 모드별 덱

| 모드 | 권장 구성 | 목적 |
| --- | --- | --- |
| 첫 만남·초반 이야기 | 내 드래곤 1마리 | 애착 형성·기본 조작 |
| 동료 모험 | 내 드래곤 + 동료 2자리 | 주인공을 유지하면서 협력 |
| 자유 대결 | 자유로운 3마리 덱 | 역할·상성·교체 전략 |

초보자 추천은 내 드래곤 + 보호 역할 + 회복·지원 역할입니다. 원소와 역할은 별개로 설계하며, 불 속성도 보호 역할을 선택할 수 있습니다. 동료는 플레이어의 주인공 자리를 대체하지 않습니다.

### 연출 방향

| 순간 | 제안 |
| --- | --- |
| 첫 탄생 | 종이 그림에 빛이 들어오고 이름에 반응 |
| 교감 | 고개 기울이기·다가오기·작은 울음·쉬기 |
| 선택 결과 | 보호막과 동료의 감사 등 행동의 의미 표현 |
| 성장 | 전후 모습 비교와 새 능력의 짧은 시연 |
| 전투 | 타격과 피해·회복·상태 변화의 명확한 연결 |

현재 파티클 개수만으로 성능 저하를 단정하지 않습니다. 고급 연출은 실제 기기에서 측정하며, 사용자의 그림을 가리는 화려함보다 반응과 의미 전달을 우선합니다.

## 5. 후순위와 결정이 필요한 사항

- 실시간 PvP·공식 랭킹: 핵심 창작 경험과 서버 판정·저장·공정성 검증 후 별도 계획으로 추진합니다.
- 장편 AI 이야기·장면마다 전체 이미지 재생성: 비용·일관성·대기 시간을 확인한 뒤 확대합니다.
- 공개 커뮤니티: 기본 비공개, 공개 확인과 콘텐츠 관리 흐름을 먼저 갖춥니다.
- 수집·상점·유료 기능: 내 드래곤의 기본 성장과 첫 이야기 완성을 막는 조건으로 두지 않습니다.
- 원작 후속 권: 독자 창작 모험과 별개입니다. 해당 권의 자료와 사용 범위를 확인한 뒤 각색합니다.
- 속성 체계, AI 결과 보관 범위, 생성 사용량, 시험 계정·기기, 공개 대상은 각 관련 단계 시작 전에 결정 사항으로 기록합니다. 이 문서만으로 운영 설정이나 과금 정책을 변경하지 않습니다.
