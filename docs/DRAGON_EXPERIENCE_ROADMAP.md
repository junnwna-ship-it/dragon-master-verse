## 1. 제품의 중심

> 내가 그린 드래곤이 내가 지은 이름으로 반응하고, 함께한 모험을 기억한다.

이 게임의 중심은 드래곤 수집이나 랭크 경쟁이 아니라 **플레이어가 직접 만든 드래곤과 이야기를 함께 만드는 경험**입니다. 덱·훈련·전투·상점은 이를 보조합니다.

- 플레이어가 주인공이며, 원작 인물은 동료·멘토·임무 제공자의 역할을 맡습니다.
- 원작 각색 모험과 사용자 창작 모험은 구분해서 표시합니다. 게임 고유 규칙을 원작 설정으로 소개하지 않습니다.
- AI는 사용자의 그림과 이야기를 보조합니다. 사용자가 결과를 확인하고 선택하며 원본을 잃지 않아야 합니다.
- 그림 실력, 이미지 생성 비용, AI 정돈 여부가 드래곤의 전투력을 결정하지 않습니다.
- 성장 후에도 처음 그린 드래곤의 특징이 유지되어야 합니다.

### DM-01. 드래곤 정체성과 그림을 보존

- [x] 브라우저 IndexedDB에서 초안을 계정별로 보관하고 편집 중 이름·원소·성격·첫 만남·성장 목표·현재 단계·고유 외형 메모를 자동 저장/복구합니다. 같은 기기의 계정별 분리이며 로그인 자체의 안전한 저장소나 암호화를 뜻하지 않습니다.
- [x] 사용자가 업로드한 원본 Blob과 선택적 AI 정돈 결과를 각각 보관하고, 둘을 비교해 선택합니다. 원본으로 돌아가도 정돈 결과를 다시 쓰기 위해 AI를 호출할 필요가 없습니다.
- [x] 드래곤 서버 등록 확인 후 영구 UUID를 기준으로 원본·정돈본·개인 약속의 브라우저 보관 앨범을 연결합니다. 숫자 UI ID는 보관 키로 사용하지 않습니다.
- [x] 페이지 재진입 및 로그인 계정 전환 시 늦게 완료된 응답이 다른 계정 초안을 덮지 않도록 사용자 ID·저장 순서를 확인합니다.
- [x] 생성 요청 전 브라우저에 요청 시도를 저장하고, 성공 응답에서 UUID를 받으면 후속 저장·화면 갱신보다 먼저 체크포인트와 이미지 앨범을 기록합니다. 재개는 확인된 UUID를 다시 읽으며, 응답이 유실되어 성공 여부를 알 수 없을 때는 중복 생성을 피하도록 새 요청을 막습니다.
- [ ] 영구 드래곤 UUID를 기준으로 그림·이야기·성장 기록을 클라우드에서 동기화합니다.
- [ ] 이름·원소·성격·성장 목표·보존할 외형 특징을 독립된 데이터로 관리합니다. 소개문은 이 데이터에서 생성합니다.
- [ ] 비공개 Storage에서 원본·AI 정돈본·성장 이미지를 별도 버전과 자산으로 동기화합니다. 현재 생성한 카드 이미지는 기존 공개 `dragon-images` 경로를 사용합니다.
- [x] 촬영 이미지의 자르기·좌우 90도 회전·정사각형 맞춤·방향 보정을 구현합니다. 원본은 유지하며 편집본을 별도로 저장합니다. 로컬 브라우저에서 편집·선택·재접속을 검증했고, 실기기 카메라와 기종별 EXIF 사진 검증은 남았습니다.
- [ ] AI 요청·응답이 유실되어도 서버에서 동일 요청을 조회/재개할 수 있는 idempotency 키와 작업 상태를 저장합니다. 현재 클라이언트 안전장치가 요청 유실 후 재시도를 막지만 서버 RPC의 idempotency는 지원하지 않습니다.

로컬 구현: 이 브라우저에서 초안과 원본·편집본·정돈본을 재방문 후 복원하고, 등록이 확인된 UUID의 개인 그림 앨범을 열 수 있습니다. 자동 테스트와 사진 편집 UI를 검증했으며 서버 생성 후 실제 계정 앨범 조회는 외부 저장 검증과 함께 남아 있습니다. **DM-01 전체 완료 기준:** 비공개 클라우드 동기화, 다른 기기 재로그인, AI 요청 재개, 실제 DB 재시도·RLS 검증까지 마쳐야 합니다.

## 4. 권장 게임 구성

### 그림과 장면

원본 그림 → 정돈 후보 → 선택된 캐릭터 → 장면별 배치 → 승인된 성장 모습으로 이어갑니다. 배경과 캐릭터를 분리하고 동일한 특징 정보를 재사용합니다. 얼굴·손·책상 등이 포함된 촬영은 자르기 안내로 줄이고, 공개 전 결과를 확인하게 합니다.

### 기억이 이어지는 이야기 예시

겁이 많은 루미가 다리를 건너지 못하는 장면에서 기다려주면 신뢰 사건을, 함께 연습하면 용기 사건을 기록합니다. 다음 이야기에서 해당 사건이 있을 때만 ‘지난번에도 함께 기다려줬잖아’ 같은 반응을 사용합니다. 모든 선택을 단순 정답/오답으로 처리하지 않습니다.

### 모드별 덱

| 모드                | 권장 구성              | 목적                     |
| ------------------- | ---------------------- | ------------------------ |
| 첫 만남·초반 이야기 | 내 드래곤 1마리        | 애착 형성·기본 조작      |
| 동료 모험           | 내 드래곤 + 동료 2자리 | 주인공을 유지하면서 협력 |
| 자유 대결           | 자유로운 3마리 덱      | 역할·상성·교체 전략      |

초보자 추천은 내 드래곤 + 보호 역할 + 회복·지원 역할입니다. 원소와 역할은 별개로 설계하며, 불 속성도 보호 역할을 선택할 수 있습니다. 동료는 플레이어의 주인공 자리를 대체하지 않습니다.

### 연출 방향

| 순간      | 제안                                     |
| --------- | ---------------------------------------- |
| 첫 탄생   | 종이 그림에 빛이 들어오고 이름에 반응    |
| 교감      | 고개 기울이기·다가오기·작은 울음·쉬기    |
| 선택 결과 | 보호막과 동료의 감사 등 행동의 의미 표현 |
| 성장      | 전후 모습 비교와 새 능력의 짧은 시연     |
| 전투      | 타격과 피해·회복·상태 변화의 명확한 연결 |

현재 파티클 개수만으로 성능 저하를 단정하지 않습니다. 고급 연출은 실제 기기에서 측정하며, 사용자의 그림을 가리는 화려함보다 반응과 의미 전달을 우선합니다.

### 2026-09-26 · DM-01-C 클라우드 저장 로컬 구현

- DB 정의: 비공개 `dragon-originals` 버킷, 소유자별 `dragon_drafts`·`dragon_assets`·`personal_dragon_profiles`와 읽기 RLS, 수정 버전 충돌 검사 RPC, 초안 ID 기준 멱등 생성 RPC를 [`마이그레이션`](../supabase/migrations/20260926120000_dm01_cloud_storage.sql)에 추가했습니다. **이 기록일 당시 미적용이었으며, 2026-09-27 적용 완료했습니다.**

- 생성: 신규 RPC는 초안 행을 잠그고 같은 초안 재호출에 같은 드래곤 UUID를 반환합니다. 기존 비멱등 RPC의 응답 유실 기록은 여전히 자동 재시도하지 않습니다. 공개 카드 그림은 도감 호환성을 위해 별도 공개 버킷에 남습니다.
- 검증 경계: 타입·린트·단위 테스트 136개·빌드는 로컬에서 확인했습니다. SQL 실 DB 적용, 비공개 객체 권한, 중단/재시도, 다른 기기 복구, 계정 간 차단은 DM-01-D에서 테스트 계정과 테스트 그림으로 검증해야 합니다. 적용 후 Supabase 생성 타입을 갱신해야 합니다. 적용 전에는 현재 서비스에 클라우드 보관이 활성화되지 않습니다.
